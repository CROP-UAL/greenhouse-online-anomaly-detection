## Historial de atribución saneado

Los commits fuente exactos contienen datos y artefactos y no deben convertirse en ancestros de `main`. La reconstrucción segura conserva por commit el nombre de autor visible en Git, la fecha y la relación entre padres. Su asunto y ficha solo indican categorías genéricas de trabajo: código Python, notebooks, documentación o configuración. No copia correos originales, URL de cuentas, SHA originales, asuntos originales, rutas fuente ni contenido de archivos. Usa correos ficticios terminados en `.invalid` para que Git pueda mostrar la autoría sin publicar direcciones personales. Los nuevos SHA identifican commits reconstruidos; no equivalen a los originales.

El procedimiento está en `shared/reporting/reconstruct_history.py`. La opción `--build` crea las referencias `refs/reconstructed_safe_v2/lightgbm` y `refs/reconstructed_safe_v2/lstm`; los merges locales `194889d` y `57786f4` las conectaron a `main` sin incorporar sus árboles. `git log --graph --oneline main` muestra las 41 contribuciones LightGBM y las 6 LSTM. Se comprobó que los 141 objetos de estos grafos no comparten ninguno con los 591 objetos de los historiales fuente, que sus 47 rutas son exclusivamente fichas JSON y que el árbol de `main` quedó idéntico al anterior al merge. Tampoco hay rutas de CSV, parquet, modelos, imágenes o PDF alcanzables desde `main`.

Esta reconstrucción sanea las contribuciones añadidas, no reescribe la historia previa del destino. Los commits previos y los dos merges tienen la identidad Git configurada localmente; esta documentación y el manifiesto de importación ya incluían URL de los repositorios fuente, y una versión anterior de la auditoría contenía correos de autores. Para eliminar también esos metadatos del historial completo haría falta una reescritura separada. Las referencias locales `refs/source/*`, `refs/reconstructed/*`, `refs/reconstructed_safe/*` y `refs/archive/*` no deben publicarse con `git push --mirror`; publicar solo `main` evita enviar esos grafos locales.

`shared/reporting/check_push.py` conserva una auditoría manual de la rama: comprueba commits, referencias fuente, rutas de datos y artefactos, salidas de notebooks, blobs superiores a 5 MB y algunos patrones reconocibles de claves privadas o tokens GitHub. El hook automático `.githooks/pre-push` se retiró a petición del usuario; la auditoría ya no se ejecuta al hacer `git push`. El usuario ha decidido mantener su identidad Git actual para los commits futuros. Esta comprobación no anonimiza la historia ya publicada ni garantiza detectar todo secreto posible.
